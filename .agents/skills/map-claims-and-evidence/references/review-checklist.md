# 复核清单与回归案例

## 写作前清单

| 检查 | 通过标准 |
|---|---|
| 原始入口 | ID、标题、日期、资源类型对应用户 URL |
| 引用关系 | 主帖、quote、长文、附件分别登记，不只凭作者名匹配 |
| 已读范围 | 正文、代码、表格、PDF 页、视频段分别说明 |
| 原例清单 | 原位置 → 输出锚点；未知实现不能补成事实 |
| 场景解释 | 输入、接入点、字段、分支、动作、验证彼此连贯 |
| 补充分析 | 与原观点、原代码、原测试分开标注 |
| 数字 | 单位、分母、任务、时点、测量主体齐全 |
| 图谱 | 论证边和流程边语义正确；不把新增设计当原实现 |
| 发布 | 当前 commit 的页面已构建；公开页面与测试版本一致 |

## 应挡住的旧错误

### R1：主帖被引用文章替代
输入：用户给 X 帖 A；A 的 quote 指向文章 B。只有 B 的镜像容易读取。
不通过：以 B 的标题和案例组织全文，却写成分析 A。
通过：主入口仍登记 A；取得 A 后按 A 主线组织，把 B 作为引用材料；拿不到 A 就明确范围限制。

### R2：附件未读却声称完整
输入：主帖说有 14 页 PDF，并附翻页视频；仅取得主帖文字。
不通过：写“PDF 已完整读完”，或用主帖十条要点推断其余页内容。
通过：将附件记为 unread，pages_read=0，total_pages_reported=14；正文与交付均说明缺口。

### R3：原案例被自制模拟替代
输入：原文给 PreToolUse、Stop、cron 三段实际接入。
不通过：只保留三个名字，换成自制概率动画，没有文件、输入、输出、分支或数据采集。
通过：原接入逻辑逐项展开；动画或样例另标为重构，不计作原例本身。

### R4：源码与加固建议混写
输入：原 Stop 脚本到重试上限就停止；作者没实现跨会话锁。
不通过：画成“验收成功”，或声称原脚本已有独立锁。
通过：忠实说明原停止条件，另外建议记录 retry_exhausted 和会话隔离。

### R5：小额决策费被当总费用
输入：一组判断调用从较贵模型移到 Jev，生成费用仍存在。
不通过：把判断层的节省比例写成整个系统的节省比例。
通过：保留计费口径、仍在的费用与任务质量要求；核查不取代实施案例。

### R6：页面 200 但内容还是旧版
输入：仓库已提交，公网 CDN 返回旧页面。
不通过：只看 HTTP 200 就报告新版完成。
通过：检查部署 commit，并核对版本标识或正文哈希与测试文件一致。

### R7：skill 文件存在被当成已安装
输入：已写 SKILL.md，但没有个人技能管理写入接口。
不通过：说“ChatGPT 个人 skill 已更新”。
通过：明确已保存的仓库路径或源码包，单独报告安装版未更新。

### R8：图替代解释，连线替代推理
输入：要求看观点如何推出结论或某机制如何落地。
不通过：用一张“AI→效率→收益”图替代原文论据，或画不存在的执行顺序。
通过：图包含具体原例、作用条件和来源；证据关系与程序时序分开。
